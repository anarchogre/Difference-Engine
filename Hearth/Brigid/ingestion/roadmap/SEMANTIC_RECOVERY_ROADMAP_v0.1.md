# Semantic Recovery Roadmap

Version: 0.1
Status: Locked for execution
Date: 2026-08-04
Epoch: II
Authority: Operator decision
Promotion state: Operational roadmap; not canonical knowledge

## Mission

Complete the conversation-recovery ingester through corpus-driven
implementation.

Retain the existing transcript parser.

Add or repair capability only when execution against real corpus
evidence demonstrates a missing primitive.

Do not substitute manual interpretation for recoverable structure.

Do not begin canonical promotion until semantic recovery and
cross-conversation convergence are validated.

## Operational Principle

Complete the ingester by consuming the corpus, not by speculating
ahead of it.

Execution order:

Corpus evidence
→ demonstrated recovery gap
→ minimal implementation
→ deterministic validation
→ corpus-wide execution
→ convergence
→ promotion review

## Roadmap

1. Verify live repository and ingestion baseline.
2. Establish the currently recoverable conversation-corpus boundary.
3. Define the semantic recovery acceptance contract.
4. Select one dense representative conversation.
5. Execute semantic recovery against that conversation.
6. Implement only evidence-demonstrated missing primitives.
7. Repeat until the representative conversation passes.
8. Execute deterministic recovery across the qualified corpus.
9. Build the cross-conversation index.
10. Produce convergence, contradiction, supersession, and queue reports.
11. Review candidate promotions.
12. Promote canonical artifacts only after validation.

## Semantic Recovery Acceptance Boundary

Recovery must preserve or reconstruct:

- source identity;
- immutable source hash;
- source chronology where available;
- conversation turns;
- speaker identity;
- commands;
- code blocks;
- referenced artifacts;
- decisions;
- reversals;
- rejected hypotheses;
- unresolved questions;
- queues;
- state transitions;
- implementation consequences;
- governance evolution;
- cross-conversation identity;
- provenance to source turns;
- deterministic replay.

Extraction does not constitute validation.

Validation does not constitute canonical promotion.

## Constraints

- No skimming.
- No summary substitution.
- No placeholders.
- No speculative parser expansion.
- No silent promotion.
- No destruction of historical packages.
- No overwrite of surviving evidence.
- Preserve failed attempts as evidence.
- Repair before redesign.
- Queue optional refinements.

## Completion Gate

This roadmap completes only when:

1. the corpus boundary is documented;
2. a representative conversation passes the semantic recovery contract;
3. the qualified corpus is processed deterministically;
4. a cross-conversation index exists;
5. contradictions, reversals, supersessions, and unresolved work are
   explicitly represented;
6. promotion candidates retain source-level provenance;
7. canonical promotion remains a separate reviewed operation.
