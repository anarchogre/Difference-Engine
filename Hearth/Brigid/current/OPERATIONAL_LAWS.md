# Operational Laws

## Constitutional Operational Laws

1. Repository-first.
2. Evidence before interpretation.
3. Recover before redesign.
4. Preserve provenance.
5. Prefer deterministic automation over repetitive manual execution.
6. New automation SHALL be validated against observed reality before becoming relied upon.
7. Workflow → Validated Automation → ADE Command where durable command integration adds value.
8. Existing repository conventions ("mortar") SHALL NOT be modified without constitutional reconciliation.
9. Operational state SHALL be updated before new operational artifacts are created.
10. Runtime state SHALL remain disposable.
11. Diagnostics SHALL be treated as evidence.
12. Git SHALL provide canonical version control.
13. GitHub SHALL serve as the canonical remote after reconciliation.
14. Repository identity SHALL be validated before any repository mutation.
15. Informational validation SHALL precede enforcement.
16. Reality is the final validator.
