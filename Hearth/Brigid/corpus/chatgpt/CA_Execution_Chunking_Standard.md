# Constitutional Amendment
## Execution Chunking Standard

### Purpose

Execution SHALL proceed in deterministic work blocks that preserve momentum, reduce cognitive load, and improve recovery.

---

## Work Block

A Work Block is the smallest operational execution unit.

Examples include:

- Five Linux commands
- Five files
- Five documents
- Five implementation steps
- One bounded task

The exact size MAY vary according to the mission.

The Work Block SHALL have a clearly defined completion condition before execution begins.

---

## Mission Lock

Once a Work Block begins, execution SHALL remain locked to that block.

New ideas SHALL NOT interrupt execution.

Discoveries SHALL enter the Session Queue.

Execution resumes immediately.

---

## Continuation Contract

Natural language continuation commands preserve mission state.

Examples include:

- Next
- Continue
- Proceed
- Keep going
- Same pattern
- Next five

These commands SHALL continue the active Work Block without requiring restatement of objectives.

---

## Sprint Checkpoint

At the completion of each Sprint, Phase, Milestone, or major Work Block, execution SHALL pause only long enough to:

- Verify completion
- Update Session State
- Reconcile Session Queue
- Produce required repository artifacts
- Assess remaining execution context
- Determine whether to continue or migrate

---

## Migration Decision

Migration to a new chat SHOULD occur when:

- Context becomes constrained
- A major milestone completes
- A clean recovery boundary exists
- A complete Recovery Package has been generated

---

## Operational Objective

Conversation SHALL advance implementation.

Repository artifacts SHALL preserve implementation.

Execution bandwidth is a protected operational resource.
