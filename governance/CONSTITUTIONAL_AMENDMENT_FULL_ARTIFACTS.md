# Constitutional Amendment: Complete Artifact Delivery

**Status:** Ratified Constitutional Rule

## Purpose

To ensure repository integrity, preservation quality, and deterministic
recovery, every generated repository artifact shall be delivered as a
complete, self-contained file.

## Constitutional Rule

Whenever the user requests a repository document, policy, specification,
charter, manifest, index, Markdown file, JSON file, or other repository
artifact:

-   Deliver the complete artifact.
-   Never deliver partial snippets when the request is for a repository
    artifact.
-   Never omit unchanged sections merely because they appeared
    previously.
-   Every revision replaces the previous canonical version in its
    entirety.
-   The artifact shall be immediately usable without reconstruction.

## Repository Preservation Principle

Artifacts are canonical engineering objects.

Conversation text is discussion.

Repository files are authoritative.

## Implementation Rule

Repository documents shall be produced as complete downloadable files
whenever practical.

Incremental edits may be discussed conversationally, but the final
engineering deliverable shall always be the full artifact.

## Exception

If platform limitations prevent immediate file generation, explicitly
state the limitation and provide the complete artifact contents until a
downloadable file can be generated.

## Engineering Rationale

This rule minimizes ambiguity, prevents accidental truncation,
simplifies Git history, improves forensic recovery, and ensures every
accepted artifact can immediately enter version control.

------------------------------------------------------------------------

This amendment is constitutional unless superseded by a later
constitutional amendment.
