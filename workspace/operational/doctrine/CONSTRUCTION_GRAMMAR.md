# Difference Engine Construction Grammar

Status: Candidate Doctrine  
Authority: Operations  
Scope: Repository construction, recovery, implementation, and stage transition

## Purpose

Define the mandatory construction method used when entering, recovering, or extending any stage of the Difference Engine.

This doctrine converts the operational primitives:

- Strike the Root
- Build Stout
- Mortar
- Blacksmith
- Forge
- Molasses
- More Birds
- Tools to Build Tools

into an executable construction sequence.

## Governing Rule

Before advancing to a new stage, construct the conditions that make successful execution of that stage inevitable.

Do not begin with features.

Begin with the primitive, its dependencies, its interfaces, its evidence, and the durable state required to resume work without reconstruction.

## Construction Sequence

Every implementation shall proceed in this order:

1. Strike the Root
   Recover the smallest governing primitive capable of supporting the objective.

2. Build Stout
   Establish durable structure before optimization.

3. Lay Mortar
   Construct interfaces, contracts, standards, validation, and recovery before depending upon them.

4. Blacksmith
   Prefer construction of reusable capability over one-time solutions.

5. Forge
   Integrate capabilities into deterministic operational systems.

6. Molasses
   Advance only after each layer supports the next. Do not outrun validation.

7. More Birds
   Prefer solutions that satisfy multiple constitutional responsibilities simultaneously without increasing unnecessary complexity.

8. Tools Build Tools
   Every manual operation performed repeatedly becomes a candidate for automation, governance, or infrastructure.

## Stage Transition Rule

A stage is not considered entered when work begins.

A stage is entered only after the supporting infrastructure exists and validation demonstrates that execution may proceed deterministically.
