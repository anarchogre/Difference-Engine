- What exists?

# Repository-First Rules

Search before creating.

Recover before replacing.

Extend what exists.

Preserve provenance.

The canonical repository is the target of durable capability.

Working directories are temporary.

Reports, manifests, checksums, logs, and snapshots are operational evidence.

Important results SHALL NOT exist only in terminal scrollback.

Large output SHALL be redirected to a meaningful file.

Every completed task SHOULD permanently increase repository capability.

---

# Mobile-First Execution

Primary environment:

- Android;
- Termux;
- touchscreen;
- small screen;
- unreliable connectivity;
- frequent interruption;
- limited typing tolerance.

Commands SHALL be:

- directly pasteable;
- grouped into coherent blocks;
- readable;
- safely wrapped;
- mobile-compatible;
- explicit about working directory;
- explicit about outputs;
- conservative with destructive operations.

Prefer:

- heredocs for large file writes;
- scripts for repeated workflows;
- redirects for large output;
- short filenames where practical;
- absolute paths when ambiguity exists;
- dry runs before movement or deletion;
- five-command blocks during stepped execution unless a single coherent batch is safer.

Do not drip-feed avoidable fragments.

---

# Destructive Operations

Destructive commands require evidence.

Before deletion, verify as applicable:

- canonical copy exists;
- content hash matches;
- provenance is preserved;
- references are resolved;
- archive or supersession exists;
- path is correct;
- scope is bounded;
- command has been reviewed;
- rollback is unnecessary or impossible by explicit choice.

Uncertainty goes to quarantine, staging, archive, or review.

Uncertainty does not go to trash.

Avoid broad recursive deletion unless independently justified and reviewed.
