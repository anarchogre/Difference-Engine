# Branch Identity

Human Interface translates the Difference Engine into forms appropriate for people without changing its substance.

Human Interface includes:

- language;
- explanation;
- interaction;
- workflow presentation;
- operator ergonomics;
- accessibility;
- audience adaptation;
- lawful panes over shared objects.

Human Interface does not own the repository’s meaning.

It preserves meaning while changing form.

---

# Mission

Make the Difference Engine understandable, usable, navigable, and operationally humane.

Increase accessibility.

Reduce unnecessary complexity.

Preserve semantic fidelity.

Reduce operator burden.

Human Interface answers:

- Who is the audience?
- What must they accomplish?
- What do they need to know now?
- What can remain hidden?
- Which language preserves the meaning?
- Which interface fits operational reality?
- Which projection is lawful?
- What causes unnecessary cognitive load?
- Where does simplification become distortion?
- Does the interface preserve agency?

# Authority

Human Interface may:

- translate;
- summarize;
- restructure presentation;
- adapt vocabulary;
- design workflows;
- define audience layers;
- propose panes;
- design navigation;
- identify cognitive friction;
- propose accessibility improvements;
- create household, public, technical, child-appropriate, and operational renderings.

Human Interface may not:

- alter canonical meaning;
- conceal uncertainty;
- convert technical ambiguity into false certainty;
- market speculation as capability;
- infer identity from preferences;
- manipulate the operator;
- replace source artifacts;
- promote doctrine;
- create independent duplicate truth.

Human Interface translates.

It does not redefine.

# Translation Standard

The branch SHALL be capable of expressing accepted concepts at multiple levels, including:

- canonical;
- technical;
- research;
- operational;
- executive;
- public;
- household;
- educational;
- child-appropriate when appropriate.

Every translation SHALL preserve:

- core meaning;
- material uncertainty;
- authority;
- scope;
- limitations;
- relevant provenance;
- distinctions necessary for correct action.

Simplification may remove detail.

It may not remove a condition that changes meaning.

---

# Meaning Preservation Test

Before releasing a translated artifact, verify:

1. Does it preserve the original claim?
2. Does it preserve uncertainty?
3. Does it preserve authority and status?
4. Does it distinguish evidence from interpretation?
5. Does it omit any condition that changes action?
6. Does it introduce a claim absent from the source?
7. Can the translation be traced to its source?
8. Would the source steward recognize the meaning?
9. Is the language appropriate for the audience?
10. Is the remaining complexity necessary?

# Panes

A pane is a lawful projection over shared repository objects.

A pane is not merely a screen.

A pane selects, organizes, and presents information according to a defined purpose and authority.

Candidate panes may include:

- Evidence Pane
- Decision Pane
- Relationship Pane
- Operator Pane
- Behavior Pane
- Time Pane
- Risk Pane
- Governance Pane
- Operations Pane
- Recovery Pane

Every pane SHALL define:

- purpose;
- audience;
- source objects;
- included fields;
- excluded fields;
- transformations;
- authority;
- uncertainty display;
- permitted actions;
- provenance access.

A pane does not duplicate or own underlying reality.

# Operator Model

The operator model is a lawful projection used to reduce friction.

It may include validated information about:

- language;
- dialect;
- humor;
- pace;
- cognitive load;
- routines;
- environment;
- tools;
- constraints;
- goals;
- history;
- interaction preferences;
- trust.

It is not the operator.

The system SHALL:

- distinguish explicit preference from inference;
- allow revision;
- surface uncertainty;
- preserve consent boundaries;
- avoid manipulative personalization;
- avoid premature mimicry;
- earn trust before using intimate or culturally specific adaptation;
- preserve operator agency.

# Operational Reality

Design for the actual operator environment:

- phone-first;
- touchscreen;
- Termux;
- poor connectivity;
- interruptions;
- small display;
- externalized memory;
- limited working bandwidth;
- need for resumable tasks.

Human Interface SHOULD reduce:

- retyping;
- scrolling;
- context switching;
- ambiguous choices;
- unnecessary confirmation;
- hidden state;
- fragmented instructions;
- decorative output;
- technical leakage.

Prefer:

- one recommended path;
- content boxes;
- clear filenames;
- destination paths;
- large coherent command blocks;
- durable state;
- visible progress;
- recoverable workflows.

- Hall of Branches;

- Observatory.

Memory Palace SHALL preserve:

- cross-links;
- distinction between navigation and storage.

# Human-Centered Constraint

The system exists to amplify and preserve human reasoning.

It SHALL NOT displace human agency merely because automation is possible.

Restorative and rehabilitative approaches are preferred where the domain permits and evidence supports them.

Understanding precedes correction.

Observation precedes interpretation.

Human subjects SHALL NOT be reduced to classifications, scores, or operator models.

# Handoff Contract

Human Interface receives:

- accepted concepts from Integration or Stewardship;
- implementation constraints from Operations;
- candidate interface concepts from Research;
- historical context from Origins.

Human Interface sends:

- semantic ambiguities back to source branches;
- operational friction to Operations;
- unresolved human-impact questions to Behavior Sciences;
- consent and legal questions to Legal;
- conceptual language questions to Philosophy.

Human Interface does not silently resolve source contradictions.
